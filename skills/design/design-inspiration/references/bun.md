## Taken

- Claims are backed by comparable tables (time, throughput, RAM) with methodology footnotes and reproduce links.
- One install command and one primary toolkit story (runtime, install, test, bundle) keep adoption paths ranked.
- Scenario matrices (cold cache, CI, no-op reinstall) teach when the number matters, not only the headline speed.
- Production quotes name concrete use (single-file executable, WebSocket fanout, serverless functions) instead of vague delight.
- Compatibility is stated as a job (drop into Node projects) so switching cost is explicit.

## Rejected

- Exact brand mark and yellow identity system to copy.
- Speed adjectives without numbers. Tables with methods transfer; "blazing fast" does not.
- Equal four-tool cards without ranking. Adopt-one-or-all still needs a primary entry.

## Not applicable here

- Store when marketing developer tools with measurable performance claims. Wrong for quiet editorial portfolios or public-sector form flows alone.
